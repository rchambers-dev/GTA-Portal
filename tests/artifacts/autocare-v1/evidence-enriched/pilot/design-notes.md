## 1. Multi-axis programme health rule

**Ratified as a Curriculum Assurance design rule from the six-KSB pilot.**

A KSB can be:

- **STRUCTURALLY MAPPED CORRECTLY**

while still having weaknesses in:

- teaching depth  
- practice  
- assessment  
- evidence visibility  

Likewise, a KSB can be:

- **SUBSTANTIVELY TAUGHT**

while having:

- **NO CORRECT STRUCTURAL PRIMARY**

Therefore programme health must **not** be reduced to one mapped/unmapped flag.

### Evidence classes that must remain separable

| Axis | Meaning |
|---|---|
| TEACHING | Concepts/skills are substantively taught in live materials |
| PRACTICE | Learners apply skills in practical/task activity |
| ASSESSMENT | Competence is checked/marked/observed |
| STRUCTURAL PRIMARY OWNERSHIP | Defensible one-Primary Block home |
| EVIDENCE VISIBILITY | Whether artefacts were available to the review |

### Issue taxonomy (continue using)

- CURRICULUM GAP  
- TEACHING DEPTH GAP  
- PRACTICE GAP  
- ASSESSMENT GAP  
- EVIDENCE VISIBILITY GAP  
- STRUCTURAL MAPPING GAP  

Absence of a supplied document must **not** be treated as proof that teaching, practice, or assessment does not exist — record **EVIDENCE VISIBILITY GAP** instead unless positive absence is confirmed.

## 2. Future product requirement — multi-standard onboarding

**RECORD ONLY. Do not implement yet.**

Once Autocare validates the model, Programme Builder should support onboarding other apprenticeship standards using the same evidence categories and methodology.

Future onboarding should ask curriculum staff for equivalent current/live evidence, including:

- current SOW / curriculum structure  
- lesson plans  
- teaching materials  
- practical/task briefs  
- assessment and marking evidence  
- progress review / impact evidence  
- programme/group/module mapping information  
- OTJ structure  
- official apprenticeship standard/version  

The Portal should then help discover, structure, map, and assure the existing curriculum.

### Longer-term authoring direction

Move away from manually created, inconsistent external curriculum documents.

Programme Builder should become the controlled curriculum-authoring source and eventually generate standardised GTA:

- lesson plans  
- practical/task briefs  
- assessment/marking documents  
- learner resources  
- review/impact documents  
- curriculum mapping outputs  
- other required programme documents  

from the structured programme model, traceable as:

**OFFICIAL STANDARD → KSB → BLOCK → SESSION → TEACHING → PRACTICE → ASSESSMENT → EVIDENCE**

Autocare remains the reference programme used to validate this generic model before other apprenticeships.
